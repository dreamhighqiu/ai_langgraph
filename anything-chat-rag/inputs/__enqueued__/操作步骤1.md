# 意图与实体识别
基于自然语言理解的助手本节涉及构建基于NLU的助手。如果您正在使用语言模型对话式人工智能(CALM)，此内容可能不适用于您。NLU(自然语言理解)的目标是从用户消息中提取结构化信息。这通常包括用户的意图以及消息中包含的任何实体。你可以在训练数据中添加额外的信息，如正则表达式和查找表，以帮助模型正确识别意图和实体。

## 步骤
 1、安装
 2、进入watch目录下
 3、在data/nlu.yaml中添加调整训练数据
 4、在config.yml中调整相关配置
 5、在domain.yml中调整意图和实体
 6、训练
 7、运行服务测试

## 训练数据
### 意图
NLU训练数据由示例用户语句组成，这些语句按意图分类。为了使意图更易于使用，请为意图命名，这些名称应与用户希望通过该意图完成的任务相关。保持名称为小写，并避免使用空格和特殊字符。
### 实体
实体是用户消息中的结构化信息片段。为了使实体提取工作正常进行，您需要或者指定训练数据来训练一个机器学习模型，或者定义正则表达式，使用基于字符模式的RegexEntityExtractor来提取实体
## 同义词
同义词映射将提取的实体与一个非字面文本值相关联，这种映射方式是不区分大小写的。当用户有多种方式指代同样的事情时，可以使用同义词。考虑提取实体的最终目标，然后据此确定哪些值应被视为等同的。
假设你有一个实体账户，你用它来查询用户的余额。可能的账户类型之一是“信用账户”。你的用户也将他们的“信用账户”称为“信用账户”和“信用卡账户”
在这种情况下，你可以将“信用卡账户”和“信用账户”定义为与“信用”的同义词:
~~~ 
nlu:
- synonym: credit
  examples: |
    - credit card account
    - credit account
~~~
然后，如果这两个短语中的任何一个被提取为一个实体，它将被映射到值"credit"。这些短语的任何其他拼写形式(例如"CREDIT"、"credit ACCOUNT")也会被映射到同义词。
同义词映射仅发生在实体被提取之后。训练数据应包括同义词示例(信用卡账户和信用账户)，这样模型就能学会将这些示例识别为实体，并用“信用”替换它们。
## 正则表达式
使用正则表达式来改进意图分类和实体提取，结合管道中的RegexFeaturizer和RegexEntityExtractor组件。
### 用于意图分类的正则表达式
通过在你的流水线中包含RegexFeaturizer组件来使用正则表达式，从而改进意图分类。在使用RegexFeaturizer时，正则表达式并不作为分类意图的规则。它仅提供一种特征，意图分类器将使用这种特征来学习意图分类的模式。目前，所有意图分类器都利用了可用的正则表达式特征。一个用于“帮助”请求的正则表达式案例:
~~~
nlu:
- regex: help
  examples: |
    - \b帮助\b
~~~
匹配的意图可能是问候、帮助我、协助或其他内容。即它们匹配的词数量尽可能少，例如，使用‘\b帮助\b’而不是‘帮助.*’，因为后者可能会匹配整个消息，而前者只匹配一个词。RegexFeaturizer为意图分类器提供特征，但它不会直接预测意图。包含足够的包含正则表达式的示例，以便意图分类器能够学习使用正则表达式特征。
### 用于实体提取的正则表达式
如果实体具有确定性结构，可以通过以下两种方式之一使用正则表达式:
正则表达式作为特征
您可以在您的NLU管道中使用正则表达式为RegexFeaturizer组件创建特征。
在使用RegexFeaturizer时，使用正则表达式的名称并不重要。在使用RegexFeaturizer时，正则表达式提供了一种特征，有助于模型学习意图/实体与符合该正则表达式的输入之间的关联。实体提取的正则表达式功能目前仅由CRFEntityExtractor组件支持。其他实体提取器，如MitieEntityExtractor或SpacvEntityExtractor，将不会使用生成的特征，其存在也不会改善这些提取器的实体识别能力。

## 配置文件config
### Tokenizers（分词器）
分词器将文本分割成词项。如果是意图识别:  
 - intent_tokenization_flag：表示是否对意图标签进行分词。设置为True，以便对意图标签进行分词。
 - intent_split_symbolsets 设置用于拆分意图标签的分隔符字符串，默认为下划线。
#### WhitespaceTokenizer
使用空格作为分隔符的分词器
- 输出：  
tokens
- 依赖
无依赖项  
- 描述  
为每个由空格分隔的字符序列创建一个标记。任何不在a-zA-Z0-9_#@&范围内的字符，若满足以下任一条件，在按空格分割前将被替换为空白符:   
  - 字符紧随空格之后:" !word""word"
  - 字符位于空格之前:"word! "→"word"
  - 字符位于字符串开头:"!word""word"
  - 字符位于字符串末尾:"word!""word"  
请注意:
  - "wo!rd"->"wo!rd"   
- Configuration
~~~ 
  pipeline:
    - name: "WhitespaceTokenizer"
    # 标记以检查是否拆分意图
      "intent_tokenization_flag": False
    # 拆分意图的符号
      "intent_split_symbol": "_"
    # 用于检测的正则表达式
      "token_pattern": None
~~~

### Featurizers（特征提取器）
文本特征提取器被分为两类:稀疏特征提取器和稠密特征提取器。稀疏特征提取器是那些返回特征向量且其中存在大量缺失值的特征提取器，例如零值。由于这些特征向量通常占用大量内存，因此我们将其存储为稀疏特征。稀疏特征仅存储非零值以及这些值在向量中的位置。这样，我们节省了大量的内存，并且能够处理更大的数据集进行训练。
所有特征化器都可以返回两种不同类型的特征:序列特征和句子特征。序列特征是大小为(token数量x特征维度)的矩阵。该矩阵包含序列中每个token的特征向量。这使我们能够训练序列模型。句子特征由一个大小为(1x特征维度)的矩阵表示。该矩阵包含整个话语的特征向量。句子特征可以用于任何词袋模型。因此，相应的分类器可以决定使用哪种特征。
#### LanguageModelFeaturizer
使用预训练语言模型，为用户消息创建向量。
- 输出
用户消息的密集特征
- 类型
密集特征化器
- 描述
为实体提取、意图分类和创建特征。使用预训练语言模型计算输入文本的向量表示。
- 配置
请在该组件之前包含一个分词器组件。通过参数model_name指定要加载的哪种语言模型。有关当前支持的语言模型的列表，请参见下表要加载的权重可以通过附加参数model_weights进行指定。如果该参数为空，则会使用表中列出的默认模型权重。


| Language Model | "model_name" | "model_weights"      |
|------------    |---------------|------------------------|
| BERT           | bert         | rasa/LaBSE              |
| GPT            | gpt          | openai-gpt              |
| GPT-2          | gpt2         | gpt2                    |
| XLNet          | xlnet        | xlnet-base-cased        |
| DistilBERT     | distilbert   | distilbert-base-uncased |
| RoBERTa        | roberta      | roberta-base            |
| camemBERT      | camembert    | camembert-base          |

除了默认的预训练模型权重外，还可以使用HuggingFace模型库提供的其他模型，但需满足以下条件(提到的文件可在模型网站上的"Files and versions"部分找到):
  - 模型架构是支持的语言模型之一(请检查config.json中的model_type是否列在table的model_name列中)
  - 模型具有预训练的TensorFlow权重(请检查文件tf_model.h5是否存在，当前不支持Safetensors格式)
  - 该模型使用默认分词器(config.json中不应包含自定义tokenizer_class设置)  
  
 以下配置加载了语言模型BERT，使用rasa/LaBSE权重:
~~~
 pipeline:
  - name: LanguageModelFeaturizer
    # 模型名称
    model_name: "bert"
    # 模型路径
    model_weights: "rasa/LaBSE"

    # 模型缓存地址
    cache_dir: null  
~~~

为了提升性能，我们推荐使用sentence-transformers/all-MiniLM-L6-V2权重模型:
~~~
pipeline:
- name: LanguageModelFeaturizer
  model_name: "bert"
  model_weights: "sentence-transformers/all-MiniLM-L6-v2"
  cache_dir: null
  ~~~
#### RegexFeaturizer（正则表达式特征化器）
使用正则表达式为用户消息创建向量表示。
- 输出
 用户消息和标记的稀疏特征sparse_features

- 依赖
tokens
- 类型
稀疏特征化器
- 描述
创建实体提取和意图分类功能。在训练期间，RegexFeaturizer创建了一个在训练数据格式中定义的正则表达式列表。对于每个regex，将设置一个功能，标记该表达式是否在用户消息中找到。之后所有特征都将被输入意图分类器/实体提取器以简化分类(假定分类器在训练阶段已经知道，这个集合特征表示某个意图/实体)。实体提取的Regex特性目前仅由 CRFEntityExtractor支持。
- 配置
  - case_sensitive:是否区分大小写 False 不区分，True区分。
  - use_word_boundaries:中文时需要添加 False。
~~~
  pipeline:
    - name: "RegexFeaturizer"
      # 文本处理默认区分大小写
      "case_sensitive": False
      # 在查找表时使用匹配词边界
      "use_word_boundaries": False。
  ~~~ 
### Intent Classifiers（意图分类器）

#### DIETClassifier(意图识别与实体提取器)
是Rasa中一个多任务NLU组件，可同时执行意图分类和实体识别。将意图分类和实体提取整合在一个组件中处理使用基于Transformer的架构，对序列和句子特征进行独立处理，支持模型检查点保存，以在训练期间保存表现最佳的模型
- 输出
 意图和意图排名

- 依赖
dense_features。
- 类型
意图识别与实体提取器

- 配置
  ~~~
  pipeline:
  - name: DIETClassifier
    # 训练步数
    epochs: 100
    # 学习率
    leraning_rate: 0.001
    use_dense_input_dropout: True
    checkpoint_model: True
    evaluate_on_number_of_examples: 100
    ~~~
- 重要提示:  
  - DIET分类器需要来自您管道中的特征提取器的分词输入和特征。
  - 在测试中，它仅被视为实体提取器，前提是其确实经过了实体识别训练。
  - 该组件在Transformer层前独立处理序列和句子特征，然后将它们拼接在一起。
  - 可通过use_dense_input_dropout参数在FFNN层与DenseForSparse层之间控制Dropout。
#### LogisticRegressionClassifier（逻辑回归分类器）

逻辑回归意图分类器，使用scikit-learn实现。
- 输出  
意图和意图排名
- 依赖   
必须存在sparse_features或dense_features。
- 描述 
这个分类器使用Scikit-learn中的逻辑回归实现来进行意图分类。不仅能使用稀疏特征，也可以使用密集特征。训练速度会更快，可以作为轻量级基准使用。使用了Scikit-learn中的基础设置，除了class_weight参数外，还使用了“balanced”设置。
- 配置
  ~~~ 
    pipeline:
    - name: LogisticRegressionClassifier
        max_iter: 100
        solver: lbfgs
        tol: 0.0001
        random_state: 42
        ranking_length: 10
    ~~~

  - max_iter: 最大迭代次数。
  - solver: 求解器，对于非常小的数据集，考虑使用liblinear。
  - tol:对优化器停止标准的容限。
  - random_state:用于在训练前打乱数据。
  - ranking_length:意图数量
#### SklearnIntentClassifier（意图分类器）
Scikit-learn意图分类器
- 输出  
意图和意图排名
- 依赖  
dense_features用户消息的稠密特征
- 描述  
sklearn意图分类器训练一个线性SVM模型，该模型使用网格搜索进行优化。
- 配置
  ~~~
    pipeline:
    - name: "SklearnIntentClassifier"
    # 指定用于C-SVM交叉验证的正则化值列表。此参数与GridSearchCV中的“kernel”超参数一起使用。
    C: [1, 2, 5, 10, 20, 100]
    # 指定用于C-SVM的内核。这与GridSearchCV中的“C”超参数一起使用。
    kernels: ["linear"]
    # Gamma parameter of the C-SVM.
    "gamma": [0.1]
    # 交叉验证的次数
    "max_cross_validation_folds": 5
    # 评估函数
    "scoring_function": "f1_weighted"

### Entity Extractors（实体提取器）

#### CRFEntityExtractor

条件随机场实体提取器
- 输出  
实体
- 依赖  
token和dense_features(可选)
- 描述  
这个组件实现了一个条件随机场(CRF)来进行命名实体识别。如果特征是稠密的则需要CRFEntitvExtractor的参数中添加"text_dense_feature"
- 配置  
  ~~~
  pipeline:
    - name: "CRFEntityExtractor"
      # 是否使用 BILOU 标记
      "BILOU_flag": True
      # 滑动窗口中要提取的特征
      "features": [
      ["low", "title", "upper"],
        [
        "bias",
        "low",
        "prefix5",
        "prefix2",
        "suffix5",
        "suffix3",
        "suffix2",
        "upper",
        "title",
        "digit",
        "pattern",
        "text_dense_features"
      ],
       ["low", "title", "upper"],
        ]
      # 最大迭代次数。
      "max_iterations": 50
      # L1正则化的权重
      "L1_c": 0.1
      # L2正则化的权重
      "L2_c": 0.1
      # 要使用的稠密特征提取器的名称。如果列表为空，则使用所有可用的稠密特征。
      "featurizers": []
      # 指示是否应将提取出的实体列表按给定实体类型拆分为单个实体
      "split_entities_by_comma":
        address: False
        email: True

#### RegexEntityExtractor
使用训练数据中定义的查找表或正则表达式提取实体
- 输出  
实体
- 依赖  
无要求
- 描述
这个组件使用查找表和训练数据中定义的正则表达式来提取实体。组件会检查用户消息是否包含查找表中的一个条目或是否匹配某个正则表达式。如果找到匹配项，该值将作为实体被提取。该组件仅使用名称与训练数据中定义的实体之一相匹配的正则表达式特征。请确保为每个实体至少标注一个示例。
- 配置
  ~~~
      pipeline:
        - name: RegexEntityExtractor
        # 文本处理将默认不区分大小写
        case_sensitive: False
        # 使用查找表来提取实体
        use_lookup_tables: True
        # 使用正则表达式提取实体
        use_regexes: True
        # 在查找表时使用匹配词边界
        use_word_boundaries: True

## 增量训练

为了提高性能，实践CDD并根据用户与你的助手交互的方式添加新的训练示例。使用`rasa train --finetune`命令初始化管道，使用已经训练好的模型，然后进一步在新的训练数据集上进行微调，该数据集包含了额外的训练示例。这将有助干缩短新模型的训练时间。
默认情况下，该命令会使用‘models/’目录中的最新模型。如果有一个特定的模型想要改进，你可以通过运行`rasa train --finetune <path to model to finetune>`来指定这个模型的路径。与从头开始训练相比，对模型进行微调通常需要更少的迭代次数来训练机器学习组件，如DlETClassifier。`--epoch-fraction`参数会使用模型配置文件中为每个机器学习组件指定的迭代次数的一部分。例如，如果`DIETClassifier`被配置为使用100个epoch，那么指定`--epoch-fraction 0.5`只会用于微调的epoch数为50个。
要能够微调模型，必须满足以下条件:  
 1.提供的配置应与用于微调该模型的配置完全相同。唯一可以更改的参数是单个机器学习组件和策略的迭代次数。  
 2.基础模型所训练的标签集(意图、实体)应该与用于微调的训练数据中存在的标签集完全相同。这意味着在增量训练过程中，你无法向训练数据中添加新的意图、实体。你仍然可以为每个现有标签添加新的训练示例。如果你在训练数据中添加了/删除了标签，那么整个流程需要从头开始重新训练。  
 3.待微调的模型应使用当前已安装的Rasa版本的最低兼容版本进行训练。
