# 账户中心一体化项目 - 面试详解

## 一、项目背景与价值

### 1.1 项目背景

面试官您好，我之前主导过一个**"账户中心一体化"**项目的测试工作。我们自研的**PlayTurbo创意平台**需要与上游的**XMP投放平台**和下游的**SS素材审核系统**实现账号体系的双向打通。

**系统角色定位**：
```
┌─────────────────────────────────────────────────────────────────┐
│                         账号一体化架构                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ┌──────────┐      ┌──────────────────┐      ┌──────────┐       │
│  │   XMP    │◄────►│   PlayTurbo      │◄────►│    SS    │       │
│  │ 投放平台  │      │  创意平台(我方)   │      │ 审核系统  │       │
│  │          │      │                  │      │          │       │
│  │ • 广告投放│      │ • 账号管理(主)   │      │ • 素材审核│       │
│  │ • 数据报表│      │ • 素材上架       │      │ • 合规检查│       │
│  │ • 效果分析│      │ • 权限中心       │      │ • 质量把控│       │
│  └──────────┘      └──────────────────┘      └──────────┘       │

│       └────────────────────┴──────────────────────┘              │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 核心业务流程

**账号生命周期管理**：
| 阶段 | 业务动作 | 数据同步范围 | 影响的功能 |
|------|---------|-------------|-----------|
| 注册 | 用户在PlayTurbo注册 | 同步到XMP、SS | 三端可登录 |
| 登录 | 单点登录(SSO) | Token共享 | 免重复登录 |
| 授权 | 分配素材/报表权限 | 权限同步到XMP、SS | 查看素材、报表 |
| 使用 | 上架素材 | XMP拉取投放、SS拉取审核 | 广告投放 |
| 变更 | 权限修改/账号过期 | 实时同步取消权限 | 功能禁用 |

**核心业务场景**：

```
【场景1：完整业务链路】
用户注册 → 登录 → 获得权限 → 上架素材 → XMP拉取投放 → SS审核通过 → 查看报表

【场景2：权限变更链路】
管理员修改权限 → 消息同步 → XMP/SS权限更新 → 用户下次操作被拦截

【场景3：账号过期链路】
账号到期 → 自动触发过期事件 → 三端同步禁用 → 投放中素材下架 → 报表仅可查看历史
```

### 难点一：三系统联调的环境与数据治理

**痛点描述**：
- 测试需同时依赖三个独立系统，任一环境故障都会阻塞测试
- 一个"注册"动作在三个系统产生数据，验证数据一致性困难
- 各系统测试数据格式、约束条件不同

**我的解决方案 - 构建"一体化测试基础设施"**：

```python
# 1. 测试数据工厂：一键生成三端联动数据
class AccountDataFactory:
    """账号测试数据工厂"""
    
    def create_full_chain_account(self, permissions: list) -> dict:
        """创建贯穿三系统的测试账号"""
        # 生成唯一标识，用于全链路追踪
        trace_id = f"TEST_{uuid.uuid4().hex[:8]}_{int(time.time())}"
        
        account = {
            "trace_id": trace_id,  # 贯穿三系统的追踪ID
            "username": f"auto_test_{trace_id}",
            "email": f"{trace_id}@test.com",
            "permissions": permissions,
            "expire_time": (datetime.now() + timedelta(days=30)).isoformat()
        }
        
        # 在PlayTurbo创建主账号
        pt_user = self.create_playturbo_account(account)
        
        # 验证同步到XMP
        xmp_user = self.wait_for_sync("xmp", trace_id, timeout=30)
        
        # 验证同步到SS
        ss_user = self.wait_for_sync("ss", trace_id, timeout=30)
        
        return {
            "trace_id": trace_id,
            "playturbo": pt_user,
            "xmp": xmp_user,
            "ss": ss_user
        }
    
    def wait_for_sync(self, system: str, trace_id: str, timeout: int) -> dict:
        """等待数据同步完成并验证"""
        start = time.time()
        while time.time() - start < timeout:
            result = self.query_system(system, trace_id)
            if result:
                return result
            time.sleep(1)
        raise TimeoutError(f"{system}系统数据同步超时: {trace_id}")
```

### 难点二：异步权限同步的验证

**痛点描述**：
- 权限修改通过MQ异步同步，黑盒测试无法直接验证消息
- 权限生效有延迟，如何确定"同步完成"的时间点？
- 账号过期后，已投放的素材如何处理？

**核心测试场景设计**：

```python
class TestPermissionSync:
    """权限同步测试用例"""
    
    def test_permission_grant_sync(self, account_factory, mq_listener):
        """测试权限授予同步到XMP/SS"""
        # 1. 创建无权限账号
        account = account_factory.create_account(permissions=[])
        
        # 2. 在PlayTurbo授予"查看素材"权限
        self.grant_permission(account, "view_material")
        
        # 3. 监听MQ消息，验证消息发出
        msg = mq_listener.wait_for_message(
            topic="permission.sync",
            filter={"user_id": account["id"], "action": "grant"},
            timeout=10
        )
        assert msg is not None, "权限同步消息未发出"
        assert msg["permission"] == "view_material"
        
        # 4. 验证XMP系统权限生效
        xmp_permissions = self.query_xmp_permissions(account["trace_id"])
        assert "view_material" in xmp_permissions
        
        # 5. 验证SS系统权限生效
        ss_permissions = self.query_ss_permissions(account["trace_id"])
        assert "view_material" in ss_permissions
    
    def test_permission_revoke_blocks_operation(self, account_factory):
        """测试权限收回后操作被拦截"""
        # 1. 创建有完整权限的账号
        account = account_factory.create_full_chain_account(
            permissions=["view_material", "publish_material", "view_report"]
        )
        
        # 2. 验证初始状态：可以正常操作
        assert self.can_publish_material(account) == True
        assert self.can_view_report_in_xmp(account) == True
        
        # 3. 收回"上架素材"权限
        self.revoke_permission(account, "publish_material")
        
        # 4. 等待同步完成（轮询+超时机制）
        self.wait_for_permission_sync(account, timeout=30)
        
        # 5. 验证操作被拦截
        result = self.try_publish_material(account)
        assert result["code"] == 403
        assert "权限不足" in result["message"]
        
        # 6. 验证XMP侧也无法使用该素材
        xmp_result = self.xmp_try_pull_material(account)
        assert xmp_result["code"] == 403
    
    def test_account_expire_cascading_effect(self, account_factory):
        """测试账号过期的级联影响"""
        # 1. 创建即将过期的账号（1分钟后过期）
        account = account_factory.create_account(
            permissions=["publish_material", "view_report"],
            expire_time=datetime.now() + timedelta(minutes=1)
        )
        
        # 2. 上架一个素材，确保正在被XMP投放
        material = self.publish_material(account)
        self.start_xmp_promotion(account, material)
        
        # 3. 等待账号过期
        time.sleep(70)
        
        # 4. 验证级联影响
        # 4.1 PlayTurbo登录被拒绝
        login_result = self.try_login(account)
        assert login_result["code"] == 401
        assert "账号已过期" in login_result["message"]
        
        # 4.2 XMP侧素材自动下架
        material_status = self.query_xmp_material_status(material["id"])
        assert material_status == "offline"
        
        # 4.3 报表仍可查看历史数据（只读）
        report_result = self.view_historical_report(account)
        assert report_result["code"] == 200
        
        # 4.4 但无法导出新报表
        export_result = self.try_export_report(account)
        assert export_result["code"] == 403
```

**我的解决方案 - 全链路可观测性测试**：

```python
# 链路追踪：通过trace_id贯穿三系统日志
class TraceAnalyzer:
    """链路追踪分析器"""
    
    def trace_permission_sync(self, trace_id: str) -> dict:
        """追踪权限同步的完整链路"""
        timeline = []
        
        # 1. PlayTurbo操作日志
        pt_logs = self.query_logs("playturbo", trace_id)
        timeline.extend(self.parse_logs(pt_logs, "PlayTurbo"))
        
        # 2. MQ消息记录
        mq_records = self.query_mq_messages(trace_id)
        timeline.extend(self.parse_mq(mq_records))
        
        # 3. XMP接收日志
        xmp_logs = self.query_logs("xmp", trace_id)
        timeline.extend(self.parse_logs(xmp_logs, "XMP"))
        
        # 4. SS接收日志
        ss_logs = self.query_logs("ss", trace_id)
        timeline.extend(self.parse_logs(ss_logs, "SS"))
        
        # 按时间排序，生成完整链路
        timeline.sort(key=lambda x: x["timestamp"])
        
        return {
            "trace_id": trace_id,
            "total_duration": self.calc_duration(timeline),
            "timeline": timeline,
            "status": "success" if self.verify_complete(timeline) else "incomplete"
        }
```

### 难点三：素材生命周期与多端数据一致性

**痛点描述**：
- 素材上架后，XMP拉取投放、SS拉取审核，三端数据需保持一致
- 素材状态变更（下架/修改/删除）需要实时同步
- 报表数据涉及多系统聚合，数据准确性如何验证？

**测试场景矩阵**：

```
素材状态 × 账号状态 × 操作 = 测试场景

素材状态: [草稿, 待审核, 审核通过, 投放中, 已下架]
账号状态: [正常, 权限变更中, 已过期, 已暂停]
操作: [查看, 编辑, 上架, 下架, 删除, 拉取, 投放]

关键场景示例:
- 素材投放中 + 账号过期 → 素材自动下架 ✓
- 素材待审核 + 权限收回 → SS无法继续审核 ✓
- 素材审核通过 + XMP拉取 → 可正常投放 ✓
- 素材已下架 + XMP尝试投放 → 返回404 ✓
```

```python
class TestMaterialLifecycle:

        campaign = self.xmp_create_campaign(xmp_material)
        assert campaign["status"] == "running"
        
        # 6. 验证PlayTurbo报表可以看到投放数据
        time.sleep(300)  # 等待报表数据同步

        assert report["impressions"] > 0
```

### 难点四：报表数据一致性验证

**痛点描述**：
- 报表数据来源于XMP，需定时拉取聚合
- 数据延迟、丢失、重复如何检测？
- 跨时区、大数据量场景的准确性验证

**我的解决方案 - 数据对账机制**：

```python
class ReportDataReconciliation:
    """报表数据对账"""
    
    def reconcile_daily_report(self, date: str, account_id: str):
        """日报数据对账"""
        # 1. 从XMP拉取原始数据
        xmp_data = self.pull_xmp_raw_data(date, account_id)
        
        # 2. 从PlayTurbo查询聚合数据
        pt_data = self.query_playturbo_report(date, account_id)
        
        # 3. 对账核心指标
        discrepancies = []
        
        metrics = ["impressions", "clicks", "conversions", "spend"]
        for metric in metrics:
            xmp_value = sum(xmp_data.get(metric, []))
            pt_value = pt_data.get(metric, 0)
            
            # 允许0.1%的误差（浮点数精度问题）
            if abs(xmp_value - pt_value) / max(xmp_value, 1) > 0.001:
                discrepancies.append({
                    "metric": metric,
                    "xmp_value": xmp_value,
                    "pt_value": pt_value,
                    "diff": xmp_value - pt_value,
                    "diff_rate": f"{(xmp_value - pt_value) / xmp_value * 100:.2f}%"
                })
        
        return {
            "date": date,
            "account_id": account_id,
            "status": "pass" if len(discrepancies) == 0 else "fail",
            "discrepancies": discrepancies
        }
```

### 4.2 问题定责SOP

```
【问题排查流程】

1. 获取trace_id
   └── 从用户反馈/日志/监控中提取

2. 查询PlayTurbo日志
   └── 确认操作是否正确发起
   └── 如果异常 → PlayTurbo问题

3. 查询MQ消息记录
   └── 确认消息是否发出

4. 查询XMP/SS接收日志
   └── 确认是否收到消息
   └── 如果未收到 → 网络或MQ问题
   └── 如果收到但处理失败 → XMP/SS问题

5. 生成问题报告
   └── 明确责任方
   └── 提供完整链路日志
   └── 给出修复建议
```

## 八、可能被追问的问题

### Q1: 如果XMP系统不配合提供Mock接口怎么办？
> "我会采取两步策略：首先，基于接口文档自己搭建Mock Server，模拟正常和异常响应，保证我方测试不被阻塞；其次，将接口契约文档化，推动建立契约测试机制，从源头解决接口不一致问题。"

### Q2: 账号过期的测试，总不能真等账号过期吧？
> "我们通过两种方式处理：一是创建**即将过期的测试账号**（比如1分钟后过期），等待触发过期逻辑；二是**Mock时间服务**，通过修改系统时间接口让账号立即过期，验证级联影响。"

### Q3: 如何保证测试数据不污染线上？
> "所有测试数据都带有**唯一标识前缀**（如`TEST_`），并在测试完成后自动清理。同时，测试环境与线上完全隔离，通过不同的数据库和消息队列。"

### Q4: 并发场景如何测试？
> "使用**pytest-xdist**进行并行测试，模拟多用户同时操作。对于竞态条件，设计了**快速连续操作**的测试用例（如登录后立即修改权限），验证系统的幂等性和顺序保证。"
