# Awesome Claude Skills GitHub 页面测试计划

## 页面概述
GitHub 仓库页面：https://github.com/ComposioHQ/awesome-claude-skills
这是一个展示 Claude AI 技能精选列表的 GitHub 仓库页面。

## 测试目标
验证页面的核心功能、UI 元素和用户体验。

## 测试范围
### P0 - 核心功能（必须测试）
1. 页面加载和基本结构验证
2. 仓库基本信息显示
3. README 内容展示
4. 文件目录导航

### P1 - 重要功能（推荐测试）
1. 社交链接功能
2. 代码片段复制功能
3. 内部链接导航
4. 响应式布局

### P2 - 辅助功能（可选测试）
1. 可访问性检查
2. 性能测试
3. 跨浏览器兼容性

## 测试场景

### 场景 1：页面加载和基本结构验证
**优先级**: P0
**描述**: 验证页面能正常加载并显示正确的标题和结构
**测试步骤**:
1. 导航到 https://github.com/ComposioHQ/awesome-claude-skills
2. 验证页面标题包含 "GitHub - ComposioHQ/awesome-claude-skills"
3. 验证页面包含 GitHub 标准导航栏
4. 验证仓库名称显示正确
5. 验证 README 区域存在

**预期结果**:
- 页面加载成功，无错误
- 标题正确显示
- 所有核心 UI 元素可见

### 场景 2：仓库基本信息验证
**优先级**: P0
**描述**: 验证仓库的基本信息显示正确
**测试步骤**:
1. 验证仓库名称显示为 "ComposioHQ/awesome-claude-skills"
2. 验证仓库描述包含 "A curated list of awesome Claude Skills"
3. 验证星标数显示（动态数据，只验证存在）
4. 验证分支数显示（动态数据，只验证存在）
5. 验证 Issues 和 Pull Requests 计数显示

**预期结果**:
- 所有仓库信息正确显示
- 计数元素存在（数值可能变化）

### 场景 3：README 内容验证
**优先级**: P0
**描述**: 验证 README 的核心内容显示正确
**测试步骤**:
1. 验证 "Awesome Claude Skills" 标题存在
2. 验证描述段落包含 "A curated list of practical Claude Skills"
3. 验证 "Quickstart: Connect Claude to 500+ Apps" 部分存在
4. 验证 "Contents" 目录存在
5. 验证技能分类列表存在（至少 3 个分类）

**预期结果**:
- README 核心内容正确显示
- 所有主要章节可见

### 场景 4：文件目录导航验证
**优先级**: P0
**描述**: 验证文件目录可以正常导航
**测试步骤**:
1. 验证文件目录表格存在
2. 验证至少 5 个目录项显示（如 .claude-plugin, artifacts-builder 等）
3. 点击一个目录链接（如 .claude-plugin）
4. 验证导航到正确的子目录页面
5. 返回主页面

**预期结果**:
- 文件目录正确显示
- 目录链接可点击并正确导航

### 场景 5：社交链接验证
**优先级**: P1
**描述**: 验证社交链接存在并可访问
**测试步骤**:
1. 验证 "Follow on X" 链接存在
2. 验证 "Follow on LinkedIn" 链接存在
3. 验证 "Join our Discord" 链接存在
4. 验证所有社交链接有正确的 href 属性

**预期结果**:
- 所有社交链接存在
- 链接指向正确的 URL

### 场景 6：代码片段复制功能验证
**优先级**: P1
**描述**: 验证代码片段的复制按钮功能
**测试步骤**:
1. 找到代码片段（如 "claude --plugin-dir ./connect-apps-plugin"）
2. 验证复制按钮存在
3. 点击复制按钮
4. 验证复制功能触发（通过检查按钮状态或提示）

**预期结果**:
- 复制按钮可见
- 点击复制按钮有响应

### 场景 7：内部锚点链接验证
**优先级**: P1
**描述**: 验证目录中的锚点链接功能
**测试步骤**:
1. 在 "Contents" 部分找到一个内部链接（如 "What Are Claude Skills?"）
2. 点击该链接
3. 验证页面滚动到对应的章节
4. 验证目标章节高亮或可见

**预期结果**:
- 内部链接可点击
- 页面正确滚动到目标位置

### 场景 8：响应式布局验证
**优先级**: P2
**描述**: 验证页面在不同屏幕尺寸下的显示
**测试步骤**:
1. 在桌面尺寸（>1200px）验证布局
2. 切换到平板尺寸（768px）验证布局
3. 切换到手机尺寸（375px）验证布局
4. 验证关键元素在不同尺寸下都可见

**预期结果**:
- 页面在不同尺寸下布局合理
- 无元素重叠或截断

## 边界测试场景

### 场景 9：网络缓慢加载测试
**优先级**: P1
**描述**: 验证页面在网络缓慢情况下的表现
**测试步骤**:
1. 模拟慢速网络（3G 速度）
2. 加载页面
3. 验证加载指示器或骨架屏显示
4. 验证最终所有内容都能加载

**预期结果**:
- 页面在慢速网络下仍能加载
- 用户体验可接受

### 场景 10：无效链接测试
**优先级**: P2
**描述**: 验证页面没有无效的链接
**测试步骤**:
1. 检查所有内部链接的 href 属性
2. 验证所有外部链接格式正确
3. 检查图片链接是否有效

**预期结果**:
- 所有链接格式正确
- 无明显的无效链接

## 错误处理场景

### 场景 11：404 页面处理
**优先级**: P1
**描述**: 验证访问不存在的页面时的处理
**测试步骤**:
1. 尝试访问不存在的页面路径
2. 验证显示 GitHub 404 页面
3. 验证有返回主页的链接

**预期结果**:
- 显示友好的 404 页面
- 提供返回导航

### 场景 12：JavaScript 禁用测试
**优先级**: P2
**描述**: 验证页面在 JavaScript 禁用时的基本功能
**测试步骤**:
1. 禁用 JavaScript
2. 加载页面
3. 验证基本内容仍能显示
4. 验证核心功能仍能工作

**预期结果**:
- 页面基本内容可见
- 核心导航功能工作

## 测试数据准备
- 无需特殊测试数据
- 使用公开可访问的 GitHub 页面

## 测试环境
- 浏览器: Chrome 最新版
- 屏幕分辨率: 1920x1080
- 网络: 正常宽带连接

## 风险评估
1. **动态内容风险**: 星标数、分支数等会变化，测试时只验证存在性
2. **GitHub 限制风险**: GitHub 可能有访问频率限制
3. **第三方依赖风险**: 页面依赖 GitHub 的 CDN 和 API

## 通过标准
- 所有 P0 场景测试通过
- 至少 80% 的 P1 场景测试通过
- 无阻塞性缺陷

## 备注
- 由于是公开 GitHub 页面，测试时需注意不要触发 GitHub 的防护机制
- 测试频率不宜过高，避免被限制访问
- 关注页面内容的更新，及时调整测试用例
