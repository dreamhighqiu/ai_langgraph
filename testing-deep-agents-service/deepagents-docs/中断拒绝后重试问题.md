# 中断拒绝后 Agent 重试问题及解决方案

## 问题描述

### 现象

当使用 LangGraph 的 Human-in-the-Loop (HITL) 中间件时，如果用户**拒绝**一个工具调用，agent 会：

1. 接收拒绝决策
2. 重新评估当前状态
3. 看到原始用户消息（如"写入文件到 /test.txt"）
4. 认为任务仍未完成
5. **再次生成相同的工具调用**
6. 再次触发中断，要求用户批准

这导致一个无限循环：用户拒绝 → agent 重试 → 再次中断 → 用户再次拒绝 → ...

### 示例

```
用户: 请在 /important.txt 写入内容：Test
  ↓
Agent: 准备调用 write_file("/important.txt", "Test")
  ↓
[中断] 需要批准
  ↓
用户: [点击拒绝]
  ↓
Agent: 收到拒绝，重新评估...
Agent: 用户要求写入 /important.txt，但还没完成
Agent: 准备调用 write_file("/important.txt", "Test")  ← 又是相同的调用！
  ↓
[中断] 需要批准  ← 又回到了这里！
```

## 根本原因

这是 **LangChain 1.0.3 的已知 bug**，已在 GitHub issue #33787 中报告。

### 技术原因

1. **状态持久化问题**：
   - Agent 的状态包含原始用户消息
   - 拒绝决策不会修改或标记原始消息
   - Agent 重新评估时，仍然看到"未完成"的任务

2. **缺少上下文信息**：
   - Agent 不知道某个工具调用已经被拒绝
   - 没有机制告诉 agent "这个操作已经被用户明确拒绝"

3. **LLM 的推理逻辑**：
   - LLM 看到用户请求："写入文件"
   - LLM 看到没有成功的 ToolMessage
   - LLM 推理：任务未完成，需要重试

## 解决方案

### 方案 1：系统提示指令（推荐）✅

在 agent 的系统提示中添加明确的指令，告诉 LLM 不要重试被拒绝的操作。

#### 实现代码

```python
system_prompt = """
你是一个智能助手。

## 重要：关于工具调用批准

某些工具调用需要用户批准才能执行。当工具调用被用户拒绝时：

1. **立即接受用户的决定** - 不要重试相同的命令
2. 解释你理解他们拒绝了该操作
3. 建议替代方法或请求澄清
4. **永远不要再次尝试完全相同的被拒绝命令**

尊重用户的决定并与他们协作。

示例：
- ❌ 错误：用户拒绝了 write_file，然后你又尝试 write_file
- ✅ 正确：用户拒绝了 write_file，你说"我理解您不想写入该文件。我们可以尝试其他方法吗？"
"""

agent = create_deep_agent(
    model=model,
    system_prompt=system_prompt,
    interrupt_on={"write_file": True}
)
```

#### 优点
- ✅ 简单易实现
- ✅ 不需要修改框架代码
- ✅ 已在 DeepAgents CLI 中验证有效
- ✅ 适用于所有 LLM

#### 缺点
- ⚠️ 依赖 LLM 的理解能力
- ⚠️ 不是 100% 保证（LLM 可能仍然重试）

### 方案 2：等待 LangChain 官方修复

LangChain 团队正在修复这个问题（PR #33789）。

#### 修复方案

官方修复会在拒绝决策后注入一个上下文消息：

```python
# 系统会自动添加这样的消息
AIMessage(
    name="human_review_system",
    content="""
    原始请求的操作：write_file("/important.txt", "Test")
    用户决定：拒绝
    原因：这是重要文件，不能删除
    
    系统已取消该操作。请不要重试相同的操作。
    """
)
```

#### 状态

- 🔧 PR #33789 已提交
- ⏳ 等待审核和合并
- 📦 预计在 LangChain 1.0.4+ 版本中发布

#### 如何使用

等待官方发布后，升级 LangChain：

```bash
pip install --upgrade langchain>=1.0.4
```

### 方案 3：前端禁用拒绝按钮（临时方案）

如果系统提示方案效果不好，可以暂时在前端禁用拒绝功能。

```typescript
// 在 InterruptActions 组件中
<Button
  onClick={() => setShowRejectForm(true)}
  disabled={true}  // 暂时禁用
  size="sm"
  variant="destructive"
  className="flex-1"
>
  <XCircle size={14} className="mr-1" />
  拒绝（暂不可用）
</Button>
```

## 测试验证

### 测试步骤

1. 启动 agent
2. 发送消息：`请在 /test.txt 写入内容：Hello`
3. 等待中断
4. 点击"拒绝"按钮
5. 观察 agent 的响应

### 预期结果

✅ **正确行为**：
```
Agent: 我理解您不想写入该文件。有什么其他方式可以帮助您吗？
```

❌ **错误行为**（如果没有系统提示）：
```
Agent: [再次尝试 write_file]
[中断] 需要批准  ← 又回到这里了
```
